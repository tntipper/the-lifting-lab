# Customer account logout custody

`202609180016_customer_account_logout.sql` and `lib/identity/customer-account-logout-repository.ts` implement the default-disabled local revocation boundary for the reconciled customer account. The migration adds no login role, credential, provider call, redirect or activation, and it is not installed on hosted staging.

Logout first serializes on the exact Supabase user and current session. It increments that user's account generation, holds active or just-completed account reads, removes every releasable final Supabase session, and cancels matching bridge, broker and provisional work. Cancellation covers the durable Shopify subject bound to the user and migration records that explicitly target the user. Subject reservations and encrypted proof evidence remain retained; logout does not unlink an identity, merge accounts or delete audit evidence. Another user's rows are unchanged.

The same session can repeat logout without incrementing the generation or replaying upstream logout. A lost commit acknowledgement returns no success and is never retried automatically; the committed local state is still revoked, and a later explicit same-session operation returns `not_required`. Logout and exact quarantine remain available when normal repository use is disabled.

Shopify documents Customer Account logout through the discovered OpenID `end_session_endpoint`, with the stored ID token supplied as `id_token_hint` and an optional configured post-logout redirect ([Customer Account API authentication](https://shopify.dev/docs/api/customer/latest#authentication)). A local access token can already be expired when the customer logs out, so the owner-held helper may return the original encrypted token bundle without treating it as data-access authority. Only after the local revocation commit does the adapter reconstruct the original authenticated-encryption context and expose the ID token alone to future server composition. It never returns the access token, refresh token, provider subject, proof receipt or encrypted bundle.

`lib/identity/customer-account-logout.ts` now composes this custody into the required local-first sequence. It starts from a freshly verified Supabase session, commits local revocation, then attempts global Supabase session invalidation even when the local commit acknowledgement is uncertain. It creates the pinned Shopify end-session redirect only after acknowledged local revocation and successful Supabase invalidation. Repository, owner or operation substitution suppresses the ID-token hint.

Fixed `POST /auth/customer/logout` is the only source route. It explicitly expires the base Supabase cookie and every supported chunk whether the outcome is confirmed or uncertain. A confirmed first logout redirects through Shopify with `id_token_hint` and the allowlisted preview `/auth` return; a repeat without an upstream hint returns locally. An uncertain local result or failed Supabase invalidation returns to the fixed sign-out error path and never redirects to Shopify. Request-scoped vault/database cleanup failure after revocation cannot restore account authority. Hosted staging remains inactive until migrations 012–016, restricted credentials, provider permissions and the reviewed configuration are installed.
