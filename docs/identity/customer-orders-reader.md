# Customer Account orders reader

`lib/identity/customer-orders.ts` is a server-only, default-disabled transport boundary for the Shopify Customer Account API 2026-07. It is not mounted to a route and cannot obtain, refresh or select a token. A future fenced account-operations gateway must supply one already-claimed access token from encrypted custody.

The reader sends one fixed POST to the staging shop Customer Account GraphQL endpoint. Its fixed query returns at most ten recent orders and ten line items per order. It requests no customer email, address, phone, payment information, status URL or provider IDs and performs no mutation. The browser-safe projection contains an order reference, timestamp, allowlisted financial and fulfillment statuses, exact GBP pence, bounded item names/quantities and truncation flags.

Transport uses TLS through the runtime, manual redirects, omitted credentials, no cache, a 5-second default total deadline and a 64 KiB body limit. Non-200, redirect, compressed, malformed, oversized, invalid UTF-8, GraphQL-error, unexpected status/currency or ambiguous money responses fail closed as an uncertain read. There is no retry. Errors contain neither the token nor provider response details.

Shopify documents the authenticated [Customer Account API endpoint](https://shopify.dev/docs/api/customer/latest) as `https://{shop-domain}/customer/api/2026-07/graphql`; the [Customer orders connection](https://shopify.dev/docs/api/customer/latest/objects/Customer) and [Order object](https://shopify.dev/docs/api/customer/latest/objects/Order) require the `customer_read_orders` scope and protected-customer-data approval. The OAuth `customer-account-api:full` token alone does not prove that shop-side permission. Activation must verify the installed Customer Account API permissions separately.

This unit does not establish token ownership, account binding, refresh, logout, pagination, hosted permission or a customer-facing order journey. Those remain responsibilities of the default-disabled account-operations repository/runtime.

## Source-only release coordinator

`lib/identity/customer-account-operations.ts` defines the repository contract and release ordering. It obtains a fresh verified Supabase session, asks the repository to claim one exact order-read operation, and accepts provider token custody only when the committed claim repeats the same user, session, operation, receipt, fence and unexpired token lifetime. After the provider read it verifies the current Supabase session again. The projection is released only after the repository acknowledges finishing that exact claim.

A changed or expired session, provider failure, malformed claim or missing finish acknowledgement triggers one same-fence hold and releases no projection. The coordinator never retries the provider request, token claim or finish. It remains synthetic-only, default-disabled and unmounted.

`202609180015_customer_account_operations.sql` and `lib/identity/customer-account-operations-repository.ts` provide the durable implementation behind that contract. One active 30-second order-read lease is allowed per reconciled Supabase user. Each claim is bound to the caller's current session UUID, latest reconciled transaction, exact Shopify proof receipt, logout generation and monotonic fence. An expired claim becomes held before a later claim can start; it is never reclaimed or replayed. Finish and hold require the original owner, session, operation and fence. A generation change invalidates finish, while an exact hold remains available even after controls are disabled.

The customer-token owner exposes only the encrypted token envelope and the metadata required to reconstruct its original authenticated-encryption context. The bridge owner has no proof-table or decryption-key access. The server adapter waits for the claim transaction's commit acknowledgement, validates every returned binding, then opens the envelope using the original proof fence. Lost claim acknowledgement causes one unfenced quarantine attempt; malformed committed claims use the returned fence. Connections with uncertain outcomes are discarded. No refresh token, ID token, subject, raw receipt or encrypted envelope crosses into the orders reader or its browser-safe result.

Migration 015 installs disabled, adds no login role or credential, and is not applied to hosted staging. Order access can continue after the short sign-in proof expires only while the exact stored Shopify access token remains unexpired. Refresh, coordinated logout generation advancement, route mounting, hosted permission verification and customer-facing UI remain later reviewed units.
