## Disabled native Git contract plan

The injected Git reader must return both exit status and stdout. In particular, `merge-base --is-ancestor` reports a non-ancestor by exit status 1 with empty stdout; accepting only an empty stdout would mistake a non-ancestor for a fast-forward. The fixed push command will have one refspec and an explicit expected-value `--force-with-lease=refs/heads/codex/tll-integration:<predecessor>` to close the remote-read/push race, plus `--no-verify` and `-c core.hooksPath=/dev/null` to avoid local pre-push hooks. Git documents that an explicit lease requires the remote ref to equal the stated value and can override the usual fast-forward rejection; therefore **both** immutable local ancestry proof and the exact lease are mandatory. No leading `+`, bare `--force`, extra refspec, origin alias, shell or ambient executable is allowed. The future process adapter must recheck selection/config immediately before a durable journal dispatch and stop on any uncertainty. Official references: https://git-scm.com/docs/git-push and https://git-scm.com/docs/git-config . This disabled unit only returns command options and source-selection evidence through injected ports; it cannot invoke a native push.

## Arming checkout separation — decision before launcher work

The source selector requires a clean tracked checkout at HEAD. A tracked false-to-true launcher arming diff in that same checkout would make selection HOLD; committing the armed launcher there would make the **armed** code the selected deployment source. Do not weaken the clean-source requirement or publish an armed commit merely to pass the gate.

Use a separate **local-only arming worktree** at execution commit A, descended from clean disabled source commit S in the fixed `implementation-integration` checkout. The arming launcher must import the reviewed selector/binding/read/push/journal modules from the fixed original checkout, not its own worktree, so the selector still proves S from the clean source root and fixed worktree config. The launcher's only publish refspec is S to `refs/heads/codex/tll-integration` under the exact predecessor lease; A must never be pushed. Record S, its committed manifest digest and predecessor separately from A and the reviewed arming diff. Both checkouts share Git config/objects, so verify effective config and both states immediately before dispatch.

The action-time arming sequence is: finish ordinary checks while all gates are false; independently review and commit A **only in the local arming worktree**, with only the approved launcher/manifest pin changes; verify source checkout remains clean at S and execution checkout clean at A; obtain fresh approval for the exact S/predecessor/manifest and one push; directly invoke the fixed launcher once; reconcile and disarm A after the run. No ordinary tests run while A is armed. Both worktrees must use the single canonical private journal. A separate one-use approval file would change the authorization model and is not used. Independent design review favored this separation; the concrete launcher/import and worktree checks still require review before arming.
