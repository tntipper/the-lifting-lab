# Stage 3 — Git-triggered Preview source proof decision

## Outcome and acceptance

Use the connected staging branch's normal Git-triggered Vercel Preview as the primary route to a current protected Preview. Accept source provenance only when a fresh Vercel project/deployment read identifies the fixed project, team, GitHub repository ID `1264363509`, `codex/tll-integration` branch, full selected SHA, `target:null`, `READY` state and immutable URL; a fresh Git read identifies the same remote SHA and hashes the activation-manifest bytes from that immutable commit; the protected branch alias resolves to that same deployment before and after deployment-bound runtime readiness; and disabled customer/cart/Edge flags are observed. A metadata string asserting a manifest hash is neither required nor sufficient. This is Git source provenance plus runtime verification, not byte-for-byte proof of Vercel's build artifact.

This decision supersedes the custom POST/`tllManifestSha256` route proposed in `2026-09-23-stage3-preview-source-readiness.md` for the **first current-source Preview**. The POST contract remains disabled and must not be used as an unreviewed fallback. A separately planned targeted deployment can be considered if the Git-triggered Preview fails, after diagnosing the reason.

## Fixed Git executable recovery — read boundary first

On this Mac, the existing CLI's `/usr/bin/git` stops at the unaccepted Xcode licence. The installed Codex runtime contains a native Git binary at one fixed absolute path. For the source-proof **read only**, pin that executable by its SHA-256, require a regular non-symlink file with no group/other write permission, and retain the existing exact command allowlist, remote URL and scrubbed process environment. Do not search `PATH`, accept an environment-supplied executable, invoke the shell wrapper, change the owner's Xcode licence, or add a push command to the read policy. If the binary is absent or changes, return the existing fixed HOLD. Verify a real local command boundary and negative executable/argument cases. Review this correction before any publication journal or push runner is added; this read recovery itself authorizes no external mutation.

The first review returned HOLD: the native binary ran built-in `rev-parse`, but the scrubbed environment omitted its HTTPS helper directory, so `ls-remote` could not dispatch `git-remote-https`. This was a test-design miss: testing only a built-in command did not cover the network helper boundary. The correction pins `GIT_EXEC_PATH` to the same fixed runtime's `libexec/git-core`, validates the directory and its exact `git-remote-https -> git-remote-http` link plus the target executable digest, and adds an offline helper-dispatch test with no URL or remote. A changed or absent helper fails closed. Re-review the corrected diff before relying on the read CLI; the publish path remains a separate unit.
