The owner authorised continuing Stage 3, but each hosted setting write, branch publication, deployment and activation still has its own reviewed action gate. No purchase or production change is in scope.

The enabled build must be a new immutable protected Preview because environment changes do not update earlier builds. Prove its actual source, alias and public/private flags; test owner-only sign-in, account, orders isolation, cart and checkout handoff without purchase. Finally switch surfaces OFF, drain sessions, retire roles and independently verify the held final state before the recovery deadline. Stop on any uncertain result; expiry alone is not cleanup.

## Why this order changed

The prior one-hour setup window spent effort on staging many values and then stopped during retirement because a role-sensitive read used the wrong Supabase API execution identity. The corrected reads retain `BEGIN READ ONLY` SQL but request the `postgres` execution identity. The old Generation 22 worker unconditionally retires logins after setup proof, so its complete lifecycle cannot serve a live sign-in test. The local activation binding still refuses `createDeployment()`; it needs a reviewed connection to the separate one-use Preview deployment worker before activation. Prepare and prove those dependencies while the site stays held; start temporary credentials only when the end-to-end test and cleanup fit comfortably inside their deadline.
