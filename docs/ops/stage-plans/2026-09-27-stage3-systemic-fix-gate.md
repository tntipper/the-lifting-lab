## Six mitigations and proof required

1. **Classify the real failure privately.** The Node database wrapper now retains only an allow-listed operation, error category/code and elapsed-time bucket. The verifier retains both connection attempts and completed-role count; the private one-use connection record can retain that fixed evidence. Application responses remain generic. Focused tests prove an authentication rejection reaches the record without its raw message or password. Before any successor run, use a fresh one-use record path; the v6 path is consumed.
2. **Rehearse the assembled route with real input flow.** The network fake now asserts the password and pinned public certificate actually passed from the verifier into the real connection wrapper. It tests transient and repeated authentication rejection, failed query denial and record-write failure. The broader local route and shutdown tests must still pass after the successor assembly is changed. These are simulations, not hosted proof.
3. **Choose a workable password proof.** The Mac has no IPv6 route to Supabase's direct database address; no direct-login result can be claimed here. The approved substitute for the next gate must combine the setup SQL's exact SCRAM-verifier comparison, the local password-forwarding test, classified bounded pooler attempts, and a final known-good connection after deliberate wrong-password probes. This is weaker than an independent direct login and must be labelled so. If an already available IPv6-capable approved host appears, a pinned-TLS direct-login proof can replace the substitute; do not buy an add-on or weaken TLS by default.
4. **Prove deployed consumers before sign-in.** A new protected Preview `GET /api/staging/consumer-readiness` checks the actual website deployment's customer, cart, provisional and bridge database settings using one fixed read-only identity query per role, only while all customer/cart/checkout controls are OFF. It returns only PASS/FAIL fields and the deployment ID. A separate `tll-broker-readiness` Edge function is built locally with a source switch OFF by default. When separately reviewed and enabled in staging, it requires the staging service key before a fixed broker-role identity read and returns only PASS/FAIL. Neither probe has been deployed or connected to the one-run coordinator yet. The protected Preview must be newly built after temporary Vercel values are installed. A settings-name inventory is not enough.
5. **Run one supervised owner journey only after readiness.** The route must cover sign-in, identity and orders, explicit guest-cart transfer, exact variant and price, checkout-page GET only, and POST logout. Continue collecting noncritical findings, but stop on wrong identity, customer-data exposure, unexpected payment destination or uncertain state. No purchase.
6. **Prove the shutdown independently.** Final evidence must show website/checkout OFF, provider disabled, database controls OFF, five roles with no login/password and zero sessions. A lost or uncertain write response requires a new read-only reconciliation and separately reviewed cleanup; never replay a consumed one-use action. The existing local shutdown and retirement tests remain mandatory regression checks.
