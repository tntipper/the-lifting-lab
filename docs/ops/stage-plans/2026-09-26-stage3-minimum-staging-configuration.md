## Order and proof

This assessor has no live access and is still disabled. An Edge secret-name listing does not prove the disabled flag's value or equality of write-only credentials; verify those separately before activation. Use the just-completed v2 Vercel inventory for planning; recheck Vercel identity and names only immediately before a later setting write through a *new* bounded plan. Do not replay v2. Record only nonsecret state. If anything differs from the expected disabled baseline, stop and reconcile before generating material.
2. **Build a new disabled successor package.** Reuse the reviewed generation/connection-validation components where still valid, but allocate a fresh generation/window identity and journal. Generate only the 16 missing Vercel credentials plus the broker database password's matching Supabase Edge entry; do not rotate the existing broker client secret or other present settings. Keep generated values in memory, wipe them on close, and stage the four switches as `false`/`disabled`. Check exact target project, branch, purpose mapping, unique vault IDs, role grants, expiry and recovery path in offline tests. This must remain disabled until independently reviewed.
3. **Stage without activating.** After fresh action-time approval, install the restricted database credentials and matching Vercel/Edge secrets in the reviewed order. Classify the existing Storefront token as a secret through a separately reviewed setting change that preserves its value and scope. Install the four disabled switches. Use one-use records and readback of names/classification/control states; write-only secret values cannot be proven equal by listing them. On any partial or uncertain write, leave all switches off, record the phase and reconcile without replay.
4. **Prove a held build.** Publish only an explicitly reviewed, protected Preview from an exact source commit once credentials are staged. Verify its Git source, immutable URL, alias, access protection and actual compiled/runtime account/cart flags remain off. Check CI. A name inventory alone cannot substitute for this build proof.
5. **Separate activation gate.** Only after the disabled Preview and restricted connections pass, prepare the provider/database/Edge/server/public activation sequence with a one-use recovery plan and separate owner approval. Finish with a no-purchase sign-in, account and cart journey. A purchase, live-store setting change or Production deployment is outside this gate.
