# Legacy product listings and exact offers (F14, partial F27)

Legacy `products.buy_url` is a reference, not proof of an exact sellable variant. It contains no current stock, approved cost, operator clearance or formula/pack approval. The comparison surfaces now use `ProductOfferLink` and the shared `resolveProductListing` classifier. Missing URLs do not generate Amazon/Bulk searches. Search URLs explicitly stored as references remain labelled searches. Direct references are labelled retailer listings with a prompt to check pack and price, never Buy or Add to cart.

Product paths are positively matched for each supported retailer; recognised category, search and promotion paths stay search-only. Unknown, cart, account and redirect paths are held, including embedded navigation-target query parameters.

The initial external destination allowlist is Amazon UK, Bulk and Myprotein on their explicit HTTPS domains. Credentials, unexpected ports, shorteners, unknown redirectors, malformed URLs and unreviewed hosts are withheld. Awin URLs must contain exactly one valid Bulk target; the code inspects and rewraps that target. Tracking follows the resolved retailer domain, not the product brand. Myprotein referral parameters cannot be appended to a TLL or other retailer URL. Retailer navigation is an affiliate relationship and is disclosed beside the link. This is destination classification, not an assertion that the retailer currently stocks the exact formula or honours a listed price.

All legacy TLL shop links are held because an unversioned URL cannot satisfy the exact-mapping and approved commercial data contract. The authoritative own-shop purchase path will require the catalogue eligibility service and a fresh approved projection. No function in this change can promote a legacy URL into an approved own-shop offer. The shop itself still needs authoritative inventory/publication containment and exact mappings; this application change does not make an unsafe Shopify variant unsellable directly.

The ARD comparison API keeps `buy_url` as null until a verified offer projection exists, and provides a separately named `retailer_url` and classification. Consumers must use the classification, not interpret any non-null URL as a purchase guarantee. Product structured data no longer invents an InStock Offer from the old price/URL fields. Exact Offer markup can return only alongside the same approved projection used by the visible page.

Stack exports and listing groups preserve explicit listing language. Opening retailer pages does not transfer a basket or promise stock. Dedicated deals-page search/promotion helpers remain separately labelled editorial navigation, never fallbacks for a product purchase.

Validation uses synthetic URLs and real component server rendering, with no outbound requests. Run `node --experimental-strip-types --test tests/offer-routing.test.mjs tests/preview-mode.test.mjs`, the full application tests/types/lint/build, and the existing preview runtime isolation check. Hosted navigation, exact mapping review, broader retailer admission, authoritative Shopify holds and final cart continuity remain separate acceptance gates. No supplier cost data, real customer fixtures, secrets, purchases or external messages are included.

URL families checked against retailer-owned pages on 15 September 2026: [Bulk product](https://www.bulk.com/uk/products/pure-whey-protein/bpb-wpc8-0000), [Bulk category](https://www.bulk.com/uk/protein/whey-protein), [Myprotein product](https://www.myprotein.com/p/sports-nutrition/impact-whey-isolate-powder/10530911/) and [Myprotein category](https://www.myprotein.com/c/nutrition/protein/protein-isolate/). These establish routing examples only; no observed price, label, availability or exact pack is approved by this change.
