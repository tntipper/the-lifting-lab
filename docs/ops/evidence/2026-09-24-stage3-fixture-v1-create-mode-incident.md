## Cause, process decision and preventive control

The native CREATE operation calls `SecKeychainCreate`, then requires `TLLFixtureFileIdentity.read` to accept the resulting file. That guard rejects any group/other permission bit. The observed `0644` file therefore makes the guard fail; it is a sufficient direct explanation for the CREATE/HOLD result. The terminal receipt does not distinguish this failure from other guards in the same expression, so another unobserved guard failure cannot be excluded. The assumption that Security.framework would create the file owner-only was not qualified by the disabled compilation or offline journal tests. The owner-only parent limited access to this synthetic file, and the fail-closed identity rule correctly prevented unverified cleanup.

The disabled repair anchors an owner-only directory descriptor, verifies its identity, resolves the fixed leaf with `fstatat`/`openat`, then checks that the newly created file is regular, owned and single-linked with the same device/inode as its descriptor. It tightens that verified descriptor to `0600` with `fchmod`, syncs, and rechecks descriptor, path and directory identity. Temporary synthetic-file tests cover a framework-style `0644` file, wrong directory identity, symlink refusal and a directory replacement during the operation; the replacement file stays `0644`. Independent Astra rereview returned GO for this disabled fix and closed the directory-replacement finding. The source-bound disabled fixture binary was rebuilt under a new receipt after archiving older artifacts: fixture source SHA-256 `7fb2673160069e91e9a6f07b0403f6a302eaf59627758d40dceadc6115445532`, disabled binary SHA-256 `14f9a2c64ad10164e173390bba628b6c039d007f22d022c9bba58f90ca05352b`. Full `npm test` passed 2,468 tests with two skipped; typecheck, targeted lint, activation manifest, live-boundary, both disabled-build identity checks and diff check passed. This is **offline evidence only**; the repair has not been tried against Security.framework.

## HOLD and next gate

The existing fixture file and `.fl` sidecar require a separate, read-only identity inventory and reviewed cleanup plan before deletion. The sidecar's behavior under `SecKeychainDelete` is unproved and must be accounted for before any successor run. Then the repaired CREATE behavior needs a new identifier, new one-use journals, exact source/artifact review, fresh local baseline and owner action-time approval. Do not reuse V1, restore its arming commit, arm a provider, or enable staging account/cart on this result. Stage 3 remains OPEN/HOLD.
