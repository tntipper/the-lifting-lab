# Stage 3 disabled native Keychain reader — verified local result

The native reader has been implemented **disabled**. It is not connected to a provider launcher and has not read the three real credential items. This is a possible preventive access path for the open credential incident, not a diagnosis of the earlier intermittent failure or approval for provider mutation.

The Swift source pins three exact service/account selectors in the file-based login keychain. Before a read it saves the current legacy Keychain interaction setting, disables interaction, and restores the prior setting before any credential output. It returns fixed, secret-free exit categories. Its actual mutable credential buffer is wiped on every outcome; framework-owned immutable data cannot be promised the same treatment. The production gate is `TLL_NATIVE_READER_ENABLED = false`.

The build script compiled a private arm64, ad-hoc-signed binary from a private source snapshot and checked source identity again before publication. The final disabled build and mode-0600 receipt are under `../implementation-state/staging/`, outside Git. `--check` verified source SHA-256 `46de62172b91f8258dd1ee1b109b984e1134c9c30416d83e6fb604e197b6daf4`, binary SHA-256 `92e4e3a57e51af29ce359bc19133e811f08857414c3e769c4b152fe1b0f5cad2`, arm64, and ad-hoc identifier `tll-provider-noninteractive-keychain-disabled-v2`. Earlier prototype artifacts were preserved privately and were not used as qualification evidence.

Injected offline tests cover selector allowlisting, interaction-setting and restoration failures, status mapping, malformed/oversized values, owned-buffer wiping, and partial/interrupted/failed private-pipe writes. Ordinary tests never invoke the production binary or a live launcher.
